## Architecture/Objective Diagnosis

The M3AE-AK/AL formulation is not rejected because it cannot learn anything:
it fit the train rows and beat the train median-box baseline. It is rejected as
the next production-facing direction because its held-out behavior is
contradictory:

- On validation, every non-table row is a false positive while four of seven
  `table` rows are false negatives.
- On test, the same pattern repeats with two high-scoring non-table false
  positives and four missed `table` rows.
- Non-table false positives outscore missed `table` rows, so the problem is
  not a simple threshold-positioning miss.
- Present-box MAE and IoU lose to the no-training M3AE-AJ median box on both
  validation and test.

This is best treated as an architecture/objective symptom:

1. The v1 model uses a compact global pooled feature for both presence and box
   residuals. It can memorize the tiny train split, but the held-out rows show
   no reliable target-conditioned spatial objectness.
2. The presence objective is a single scalar BCE over only 11 train rows with
   four negatives. It does not explicitly penalize high objectness on hard
   non-table negatives beyond the scalar label.
3. The box residual head can improve train geometry while still producing
   held-out boxes worse than the median baseline, so train residual fit is not
   enough to authorize crop-normalization or recognizer work.
4. The failure survives the M3AE-AN threshold sweep and M3AE-AN found no
   packet, split, tensor-hash, target-presence, or schema invalidation.

## Rejected Workarounds

### Product Threshold Selection

Rejected. M3AE-AN reported threshold sweep behavior without selecting a
threshold. Validation best accuracy remains below the required gate, and the
score ordering is contradictory because high-scoring non-table rows outscore
missed `table` rows. Selecting a threshold would hide, not fix, the target
objectness failure.

### Crop-Normalization Ablation

Rejected. The current detector does not meet validation/test presence or box
baseline gates. Running crop-normalization ablation now would compare crop
policies using a detector that cannot separate held-out `table` target
presence from non-table rows.

### Recognizer Training Or Broad Evaluation

Rejected. The detector/crop stage has not produced a trustworthy held-out
normalization signal. Recognizer training, controlled clip-heldout evaluation,
or broad 75/95-label work would skip the active Detector 0 blocker.

### Repeat v1 With More Epochs Or Hyperparameters Only

Rejected. M3AE-AL already fit train. The blocker is held-out behavior under
the current formulation, not lack of train optimization. A future trainable
slice must change the architecture/objective so it directly attacks hard
non-table objectness and held-out box geometry.

### Median Box As Detector

Rejected. M3AE-AJ remains the baseline bar and comparison target, but it is
not a runtime detector because it has no presence model.

### Packet Mutation Or Schema Remediation

Rejected for this design. M3AE-AH found no concrete packet/tensor/schema
breakage, and M3AE-AN found no held-out comparison invalidation. If future
evidence finds such a concrete invalidation, it should route to
`detector0_union_target_data_or_schema_remediation`, but this slice does not
have that evidence.

### Pretrained, Generated Label, Brev, Or Reduced Claim Escape Hatches

Rejected. Pretrained detectors/landmarks/backbones, generated pseudo-labels,
new source approval, Brev spend, product threshold promotion, model export,
model-card promotion, and final-readiness claims are outside this mission and
outside the promoted no-pretrained lane.

## Selected Future Architecture/Objective Remediation

Selected future action:
`detector0_union_target_architecture_microprobe_v2`.

Selected future formulation:
`spatial_objectness_anchor_residual_union_target_microprobe_v2`.

This is a bounded local microprobe design, not a training run in this mission.
It changes the v1 scalar presence/global residual design into a scratch spatial
objectness and box-residual objective while preserving the same approved data,
target, and source boundaries.

### Inputs

- Source: current approved Detector 0 packet only.
- Tensor key: `rgb_regions`.
- Region: `full_frame_reference`.
- Frame: packet `frame_index` only.
- Resolution: retain `96x96`.
- Channels: RGB plus deterministic `x_norm` and `y_norm` coordinate channels.
- No image/tensor payload loading in this design slice.
- No pretrained features, external detector outputs, generated labels, new
  sources, packet mutation, row addition, or label expansion.

### Architecture Sketch

```text
input: 5 x 96 x 96
scratch stem: Conv2d + GroupNorm + SiLU
scratch blocks: stride to a retained 12 x 12 spatial map
objectness head: 1 x 12 x 12 logits
box head: 4 x 12 x 12 bounded residuals
presence score: max sigmoid(objectness logits), reported at fixed 0.5
box prediction: residual at the selected or target cell plus M3AE-AJ median anchor
```

The important change is that objectness stays spatial. V1 reduced the frame to
a global pooled vector before making a single presence decision. V2 must force
the model to learn where the union/contact target would be and must penalize
non-table rows for any high objectness cell.

### Objective Sketch

Future v2 loss:

```text
total_loss =
  balanced_focal_bce(objectness_heatmap, target_heatmap_or_all_zero_absent_map)
  + hard_negative_max_objectness_penalty over absent rows
  + SmoothL1Loss(predicted_box_residual, target_residual) over present rows
  + 0.25 * (1 - IoU(predicted_box, target_box)) over present rows
```

Target heatmaps must be derived only from the existing manual/manual-corrected
union/contact target boxes. Absent non-table rows use an all-zero heatmap. Box
loss remains masked out for absent rows. The M3AE-AJ train median box remains
the anchor and baseline.

### Local No-Spend Bounds

- Device: local CPU by default; local MPS is allowed only if available.
- Brev: no sync, SSH, remote training, or compute.
- Dataset: the same 32-row approved packet used by M3AE-AL and M3AE-AN.
- Epoch cap: 300.
- Batch: full train split batch is acceptable for deterministic train-fit
  proof.
- Seed: fixed and recorded in the future receipt.
- Required output: row-level train/validation/test predictions, presence
  scores, predicted boxes, per-row MAE/IoU, median-baseline comparison, and a
  report-only threshold sweep with no product threshold selection.
